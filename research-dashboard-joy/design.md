# SiOCN 선택식각 연구 대시보드 — 설계안 (초안, 2026-11-05)

## 1. 목적과 위치

- **목적**: CF₄+H₂O 기반 AFS 선택 식각 (SiOCN vs 구 SiOC) 연구의 전 과정을 한 페이지에서 조망한다 — 목표·조건 공간·판정이 끝난 가설·측정 주의·다음 후보를 분리해 보여 주는 것이 핵심이다. 이 주제는 정식의 내년까지의 주 연구 주제다.
- **위치**: 반도체 백과 사이트 (semiconductor-notes, GitHub Pages)의 홈 아래 별도 섹션. 제안 경로: `/research/siocn-ale/`. 백과 본문 (학습 노트)과 달리 이 페이지는 **진행 중인 연구의 현황판**이므로, 홈 대시보드의 최근 논문 위젯처럼 데이터 파일에서 생성되는 동적 성격의 섹션으로 분리한다.
- **공개 범위**: 전부 공개 (2026-11-05 정식 결정 — 미발표 수치 포함). 대시보드 상단에 공개 상태와 데이터 기준일을 명시한다.

## 2. 설계 원칙 — 대시보드는 "뷰"다

원본 데이터는 대시보드가 갖지 않는다.

| 층 | 원본 | 역할 |
| --- | --- | --- |
| 실험 로그 (원본) | Google Sheets 「SiOCN CCP」 | 조건·두께 실측의 단일 진실 원본 |
| 토론·판정 | Notion 실험 보드 | 가설 상태, 교차검토, 정식 결정의 기록 |
| 구조화 근거 | goals/doe-ai (GOAL.md, 분석 정리본, 제원 시트) | 해석·경계조건 |
| **대시보드 (뷰)** | **data.json → 정적 HTML** | 위 원본에서 뽑은 현황 요약. 직접 편집하지 않는다 |

- 페이지에 보이는 모든 수치는 `data.json`에 먼저 들어가고, HTML은 그 렌더링 결과다. HTML을 손으로 고치는 방식 (2026-11-04 papers 페이지 손패치 같은)은 임시 조치로만 허용하고, 정식 경로는 항상 data.json 경유다.
- 수치는 원본 실측 인용만 쓴다. 소스에 없는 값은 JSON에서 `null`, 화면에서는 "기록 없음"으로 표시한다 — 0이나 추정값으로 채우지 않는다.
- 해석 문장은 [추론] 표기를 유지한다. 가설 상태판의 "기각됨"은 사전에 고정한 판정 기준에 근거한 경우만 쓴다.

## 3. 페이지 구성 (7개 절) 과 근거

1. **연구 개요** — 목표 선택비 10:1 (정식 확정 성공 기준), 우선순위 (구 SiOC 1순위), 화학계 (CF₄+H₂O 「동일」 / NF₃·NH₃ 「유사」), 사이클 구조, 메커니즘 한 줄, 장비 요약. 연구의 고정점이라 데이터가 쌓여도 거의 변하지 않는다.
2. **실험 회차 타임라인** — 날짜순 회차 (2026-08-29 ~ 2026-11-04, 8건). 회차마다 조건·핵심 결과·판정을 한 행에. "무엇을 돌렸고 어떻게 결론났는가"의 이력이 여기서 완결된다.
3. **조건 지도** — 시도한 조합을 (온도 × H₂O UI × Modi 시간 × 파워)로 펼친 표 + 결과 방향. 아직 비어 있는 조합이 눈에 보이는 것이 목적 — 다음 실험 후보 선정의 입력이 된다.
4. **가설·판정 상태판** — 재현됨 / 기각됨 / 미해소 3분류. 각 가설에 근거 회차와 판정일을 단다. 연구가 진전될수록 미해소가 양쪽으로 갈리는 것이 진척의 지표다.
5. **측정 기준·주의** — 엘립소 ±10 Å 기준, 막 소진 사례, 샘플 재활용 교락, H₂O 보정표 등 해석 규칙. 수치를 읽기 전에 걸러야 할 렌즈를 고정해 둔다.
6. **다음 실험 후보** — 상태 (미결정/보류) 포함. 정식 결정 전에는 실행 항목으로 표시하지 않는다.
7. **관련 논문** — 보유 목록 (137편) 중 AFS·SiOCN 직결분만 추린 목록, DOI 링크. 전체 목록은 백과 보유 목록 페이지 (/papers/)로 연결한다.

## 4. 데이터 스키마 (data.json)

```
meta            제목·기준일·원본 소스·표기 규약 (Δ 부호, 오차 기준)
overview        목표 (선택비·우선순위·출발점), 화학계, 재료, 메커니즘, 장비 요약
timeline[]      {date, label, chemistry, conditions, key_result, verdict}
condition_map[] {date, temp_C, h2o_ui, modi, power_W, pressure_mTorr, mode,
                 *_epc (풀사이클, Å/cycle) 또는 *_delta (단독·총량, Å),
                 selectivity_siocn_sioc, direction}
hypotheses[]    {statement, status (재현됨|기각됨|미해소), evidence, asof}
measurement_notes[] {title, body}
next_candidates[]   {title, reason, status}
papers[]        {authors, year, title, journal, doi, note}
links           원본 로그·실험 보드·보유 목록으로의 연결
```

- `condition_map`에서 풀사이클 행은 EPC (Å/cycle) 필드 (`*_epc`), Modi 단독·총량 행은 Δ (Å) 필드 (`*_delta`)를 쓴다 — 두 종류를 한 열에 섞지 않기 위해서다. 렌더러는 있는 필드만 표시하고 없으면 "기록 없음"을 낸다.

## 5. 갱신 흐름 (빌드 파이프라인)

```
① 실험 종료 (정식)
② Joy 정리 — 실험 보드 행 게시 (수치 전문 + 판정) · data.json 갱신 (타임라인·조건 지도·가설 상태)
③ 빌드 — 반도체 백과 빌드 체인에 연구 대시보드 생성 단계 추가
     build_research.mjs (가칭): data.json → research/siocn-ale/index.html
     데이터 파일 위치: 레포 research/siocn-ale/data.json 을 정본으로 둔다
     (이 초안 폴더의 data.json이 그 시드)
④ 검수 — Joy가 렌더 결과와 원본 시트·보드 수치를 대조
⑤ push — 기존 승인 카드 경로 (GitHub 커넥터). 빌드 대행은 OpenClaw (cudilinux)에 위임 가능 (2026-11-04 정식 빌드 대행으로 검증된 방식)
```

- 갱신 주체·검수·승인의 분리는 기존 협업 체계 (Joy=정리·대조, Claude=교차검토, OpenClaw=빌드 대행, 정식=결정·승인)를 그대로 따른다.
- 가설 상태 변경 (미해소 → 재현됨/기각됨)은 실험 보드에서 교차검토가 끝난 뒤에만 data.json에 반영한다. 대시보드가 보드보다 먼저 단정하지 않는다.

## 6. 메뉴·내비게이션 구조 결정 (2026-11-05 피드백 반영)

- 피드백: 초안 v1은 7개 절 전부를 한 페이지에 세로로 나열해 가독성이 떨어진다 — 메뉴화가 필요하다 (2026-11-05 정식).
- 선택지:
  - **(A) 탭형 단일 페이지** — 한 파일 안에서 상단 메뉴 (탭)를 눌러 해당 섹션만 보여 준다. 파일 1개·빌더 1개를 유지하고, data.json → 단일 HTML이라는 기존 설계 (§2·§5)를 그대로 쓸 수 있다. 단점은 섹션 구분이 URL 해시 (#timeline 등)로만 되고, 특정 섹션을 외부에서 직접 가리키기 어렵다는 점이다.
  - **(B) 섹션별 분리 페이지** — 개요/타임라인/조건 지도 등을 각각 별도 HTML로 뽑는다. 섹션별 URL·북마크·공유가 깔끔하고 섹션이 커져도 독립 관리가 된다. 단점은 빌더가 여러 파일을 관리해야 하고, 절 간 이동 동선과 공통 헤더 유지가 번거로워진다는 점이다.
- **초안의 선택: (A) 탭형 단일 페이지로 구현했다** (index.html v2, 2026-11-05). 현 단계에서는 데이터 규모가 작고 빌드 체인을 단순하게 유지하는 것이 우선이라 (A)가 맞다. 기본 표시 탭은 개요, 탭 바는 상단 고정 (sticky)에 모바일에서는 가로 스크롤, 긴 표는 탭 안에서 소제목으로 나눴다 — 타임라인은 시기별, 조건 지도는 날짜별, 가설 상태판은 상태별, 관련 논문은 주제별.
- repo 편입 시 재검토 조건: 특정 섹션을 외부에서 직접 링크할 일이 잦아지거나 한 섹션 (예: 타임라인)이 독립 페이지급으로 커지면 (B) 전환을 검토한다. data.json 스키마는 어느 쪽으로 가든 그대로 쓸 수 있게 절 단위로 분리돼 있다 (§4).
